# API сервера

Базовый адрес: `http://localhost:5416`

Тело POST-запросов передаётся в JSON:

```http
Content-Type: application/json
```

Для защищённых запросов требуется заголовок:

```http
token: <токен пользователя>
```

Токен возвращается при регистрации и входе как обычный текст, без JSON-кавычек.

## POST /register

Регистрация пользователя.

**Тело запроса:**

```json
{
  "login": "conductor01",
  "password": "1234",
  "name": "Алексей"
}
```

| Поле | Тип | Требования |
|---|---|---|
| `login` | string | Непустой, уникальный |
| `password` | string | Непустой |
| `name` | string | Непустой |

**Ответы:**

| Код | Тело |
|---|---|
| 200 | Токен пользователя |
| 400 | `wrong data schema` — одно из полей пустое |
| 403 | `user with this login already exists` — логин занят |

## POST /login

Вход в учётную запись.

**Тело запроса:**

```json
{
  "login": "conductor01",
  "password": "1234"
}
```

| Поле | Тип | Описание |
|---|---|---|
| `login` | string | Логин |
| `password` | string | Пароль |

**Ответы:**

| Код | Тело |
|---|---|
| 200 | Токен пользователя |
| 403 | `wrong credentials` — неверный логин или пароль |

Повторный вход возвращает существующий токен.

## POST /actOutcome

Сохранение изменения безопасности и лояльности.

**Заголовок:** `token`

**Тело запроса:**

```json
{
  "reason": "passenger_warning",
  "safety": 5,
  "loyality": -3
}
```

| Поле | Тип | Описание |
|---|---|---|
| `reason` | string | Причина изменения |
| `safety` | integer | Приращение безопасности |
| `loyality` | integer | Приращение лояльности |

Передаются изменения, а не итоговые значения. Положительное число увеличивает показатель, отрицательное уменьшает.

Поле лояльности называется **`loyality`**.

**Успешный ответ:** `200 OK`

```text
ok
```

Каждый запрос сохраняется отдельно. Повторная отправка одинакового запроса повторно учитывает изменения.

## GET /stats

Получение профиля и статистики текущего пользователя.

**Заголовок:** `token`

Тело запроса отсутствует.

**Успешный ответ:** `200 OK`, JSON.

```json
{
  "name": "Алексей",
  "login": "conductor01",
  "safety": 75,
  "loyality": 67,
  "experience": 1500,
  "achievements": ["ACH_PET_01"]
}
```

| Поле | Тип | Описание |
|---|---|---|
| `name` | string | Имя пользователя |
| `login` | string | Логин |
| `safety` | integer | Безопасность, от 0 до 100 |
| `loyality` | integer | Лояльность, от 0 до 100 |
| `experience` | integer | Общий опыт |
| `achievements` | string[] | Идентификаторы достижений |

Безопасность и лояльность рассчитываются как `70 + сумма сохранённых приращений`. Итог ограничивается диапазоном `[0, 100]`.

Опыт начисляется за:

| Событие | Опыт |
|---|---|
| Обычное достижение | 1000 |
| Скрытое достижение | 1500 |
| Завершение сценария | 500 |

## POST /achievement

Сохранение достижения.

**Заголовок:** `token`

**Тело запроса:**

```json
{
  "id": "ACH_PET_01"
}
```

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | Идентификатор достижения |

**Допустимые идентификаторы:**

| Идентификатор | Тип | Опыт |
|---|---|---|
| `ACH_PET_01` | Обычное | 1000 |
| `ACH_PET_02` | Обычное | 1000 |
| `ACH_PET_03` | Обычное | 1000 |
| `ACH_PET_04` | Обычное | 1000 |
| `ACH_PET_05` | Скрытое | 1500 |
| `ACH_PET_06` | Скрытое | 1500 |
| `ACH_NOISE_01` | Обычное | 1000 |
| `ACH_NOISE_02` | Обычное | 1000 |
| `ACH_NOISE_03` | Обычное | 1000 |
| `ACH_NOISE_04` | Обычное | 1000 |
| `ACH_NOISE_05` | Скрытое | 1500 |
| `ACH_NOISE_06` | Обычное | 1000 |
| `ACH_NOISE_07` | Скрытое | 1500 |

**Ответы:**

| Код | Тело |
|---|---|
| 200 | `ok` |
| 400 | `unknown achievement` — неизвестный идентификатор |

Повторная отправка сохранённого достижения возвращает `200 OK`. Новая запись не создаётся, опыт повторно не начисляется.

## POST /scenarioComplete

Сохранение завершения сценария.

**Заголовок:** `token`

**Тело запроса:**

```json
{
  "runId": "run-001",
  "scenarioId": "pet"
}
```

| Поле | Тип | Требования |
|---|---|---|
| `runId` | string | Непустой идентификатор прохождения |
| `scenarioId` | string | `pet` или `noise` |

Клиент задаёт `runId`: один идентификатор для сценариев одного прохождения, новый — для следующего прохождения.

**Ответы:**

| Код | Тело |
|---|---|
| 200 | `ok` |
| 400 | `wrong data schema` — пустой `runId` или недопустимый `scenarioId` |

Каждое новое завершение даёт 500 опыта. Повторная отправка той же комбинации пользователя, `runId` и `scenarioId` не начисляет опыт повторно.

## GET /leaderboard

Получение рейтинга всех пользователей.

**Заголовок:** `token`

Тело запроса отсутствует.

**Успешный ответ:** `200 OK`, JSON-массив.

```json
[
  {
    "name": "Алексей",
    "login": "conductor01",
    "experience": 1500,
    "achievements": 1,
    "safety": 75,
    "loyality": 67
  }
]
```

| Поле | Тип | Описание |
|---|---|---|
| `name` | string | Имя пользователя |
| `login` | string | Логин |
| `experience` | integer | Общий опыт |
| `achievements` | integer | Количество достижений |
| `safety` | integer | Безопасность |
| `loyality` | integer | Лояльность |

Сортировка: по убыванию опыта, при равном опыте — по возрастанию имени.

Пагинации и фильтров нет. Возвращаются все пользователи.

## Общие ошибки

Ошибки возвращаются обычным текстом.

| Код | Тело | Причина |
|---|---|---|
| 403 | `unauthorized` | Переданный токен не найден |
| 404 | `Not found` | Неизвестный путь или неподдерживаемый метод |
| 500 | `error` | Ошибка обработчика, включая ошибку разбора JSON |
| 500 | `Внутренняя ошибка сервера` | Ошибка внешнего обработчика сервера |

Для отсутствующего заголовка `token` отдельный ответ не предусмотрен. Отсутствующие поля JSON не проверяются единообразно: ответ `400` не гарантируется.
